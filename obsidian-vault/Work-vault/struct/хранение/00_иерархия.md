# Доклад: Роль иерархии классов `p1`–`q9` в обработке данных устройства UX‑8C

## 1. Введение
Ранее мы подробно разобрали цепочку контроллеров (`a1` → `w0` → `h0` → `m0` → `o0`), которые непосредственно управляют устройством, формируют команды и обрабатывают входящие потоки. Однако эти контроллеры не существуют изолированно – они **опираются на модель устройства**, которая содержит все параметры сканирования, калибровки, размеры кадров и настройки. Эта модель реализована в иерархии классов, уходящей корнем в `p1` и заканчивающейся конкретным классом `q9` для UX‑8C.

**Цель данного доклада** – показать, как эта модель построена, как она связана с контроллерами и как участвует в процессе обработки данных (от приёма сырых байт до формирования ответных команд). Мы рассмотрим все классы цепочки: `p1` → `b1` → `x0` → `n0` → `q9`, а также затронем дополнительные классы (`l0`, `o1`, `z0`), участвующие в сохранении и загрузке параметров.

## 2. Базовый класс `p1` – хранилище параметров устройства

### 2.1. Основные поля
| Поле | Тип | Назначение |
|------|-----|------------|
| `f9522b` | `String` | Уникальное имя устройства (например, "UX‑8C"). |
| `f9523c` | `String` | Полная строка идентификации (например, "UX-8C A001"). |
| `f9524d` | `String` | Серийный номер (извлекается из строки). |
| `f9525e` | `char` | Буква, обозначающая версию (A, B, C...). |
| `f9526f` | `int` | Числовой код, соответствующий букве версии (используется для команд). |
| `f9528h` | `int` | Текущий индекс зума (0–3). |
| `f9529i` | `int` | Текущее значение усиления (30–105). |
| `f9527g` | `a` (внутренний класс) | **Главный контейнер параметров сканирования** (см. ниже). |
| `f9530j` | `b` (внутренний класс) | Дополнительная информация (например, версия прошивки). |

### 2.2. Внутренний класс `a` – параметры сканирования
| Поле | Тип | Назначение |
|------|-----|------------|
| `f9531b` | `float` | Частота (МГц). |
| `f9532c` | `float` | Длина волны. |
| `f9533d` | `boolean` | Флаг, указывающий, поддерживается ли режим с высокой частотой. |
| `f9535f` | `int` | **Количество линий в кадре** (обычно 128). |
| `f9536g` | `int` | **Количество точек на линию** (обычно 512). |
| `f9537h[4]` | `int[]` | Коэффициенты для глубины (для каждого зума). |
| `f9538i[4]` | `int[]` | Коэффициенты для динамического диапазона. |
| `f9539j[256]` | `int[]` | Таблица отображения значений (вероятно, для цветокоррекции). |
| `f9540k` | `float` | Масштабный коэффициент (используется для вычисления скорости звука). |
| `f9541l[4]` | `int[]` | Значения для пересчёта глубины в зависимости от зума. |

**Методы:**
- `a(int i4)` – возвращает `f9540k / f9541l[i4]` – коэффициент для вычисления времени задержки.
- `b(int i4)` – вычисляет скорость (780000 / a(i4)), используется для допплеровских режимов.

### 2.3. Внутренний класс `b` – информация о прошивке
| Поле | Тип | Назначение |
|------|-----|------------|
| `f9543b` | `int` | Тип устройства. |
| `f9544c` | `int` | Версия. |
| `f9545d` | `int` | Код. |
| `f9546e` | `int` | Дополнительный код. |
| `f9547f`...`f9550i` | `String` | Различные строковые идентификаторы. |

### 2.4. Статические элементы
- `static z0 f9515l` – глобальный объект для сохранения настроек (persistence). Устанавливается через `D(z0)`.
- Константы `f9516m` (0) … `f9520q` (4) – вероятно, коды режимов (но не используются в `p1` напрямую).

### 2.5. Роль в обработке данных
- Контроллеры (`a1` и наследники) получают доступ к модели через поле `f9561c` (типа `p1`). Оттуда они извлекают:
  - Размеры кадра (`w()` и `E()`).
  - Частоту и глубину для формирования метаданных (`m2.u`).
  - Текущие значения усиления и зума.
- Входящие пакеты (например, 512‑байтовые) обновляют состояние модели через вызовы `H(int)` (усиление) и `I(int)` (зум), которые сохраняют изменения и синхронизируют с постоянным хранилищем (`o1` и `z0`).

## 3. Наследник `b1` – промежуточный слой
Класс `b1` наследует `p1` и переопределяет только метод `y()` (создание контроллера). В базовой версии он возвращает `a1`. Это обеспечивает совместимость с устройствами, не требующими расширенных режимов.

## 4. Наследник `x0` – расширенные параметры

### 4.1. Добавленные поля
| Поле | Тип | Назначение |
|------|-----|------------|
| `f9683s` | `a` (внутренний класс) | Хранит **матрицы преобразования** для цветовых режимов (коэффициенты для коррекции цвета, фокусировки, стееринга). |
| `f9684t` | `boolean` | Флаг включения гармоник (harmonic). |
| `f9685u` | `int` | Глубина (индекс, 0–3). |
| `f9686v` | `int` | Положение фокуса (индекс). |
| `f9687w` | `int` | Уровень акустической мощности (0–100). |
| `f9688x` | `boolean` | Флаг компундинга (усреднение кадров). |
| `f9689y[8]` | `int[]` | Значения усиления по 8 каналам (V‑gain). |
| `f9690z` | `int` | Уровень усиления (enhance) – 0..4. |

### 4.2. Внутренний класс `a` (матрицы)
| Поле | Тип | Назначение |
|------|-----|------------|
| `f9691b` | `int` | Количество цветовых карт. |
| `f9692c` | `int` | Количество точек в цветовой карте. |
| `f9693d[4][4]` | `float[][]` | Матрица для B‑режима (коэффициенты). |
| `f9694e` | `int` | Количество точек для цветного режима. |
| `f9695f[4][4]` | `float[][]` | Матрица для цветного режима. |
| `f9696g` | `float` | Коэффициент для обычного режима. |
| `f9697h` | `float` | Коэффициент для режима с гармониками. |
| `f9698i` | `int` | Количество значений PRF (частоты повторения). |
| `f9699j[9]` | `int[]` | Значения PRF. |

### 4.3. Конструктор `x0(String str)`
- Загружает параметры из постоянного хранилища (`o1.d(null)`):
  - `f9685u` (глубина) – по умолчанию 70.
  - `f9690z` (enhance) – по умолчанию 2.
  - `f9686v` (фокус) – по умолчанию 3.
  - `f9684t` (гармоники) – по умолчанию true.
  - `f9689y[i]` (V‑gain) – по умолчанию 127 (для каждого канала).
- Это позволяет сохранять настройки между сессиями.

### 4.4. Роль в обработке
- `x0` предоставляет методы `l0()`, `n0()`, `o0()`, `p0()`, `j0()`, `k0()` и др., которые вызываются контроллерами (`w0`, `h0`) при изменении параметров.
- Эти методы не только обновляют поля, но и сохраняют изменения через `o1` и `z0`.
- Матрицы `f9683s` используются контроллером `w0` и `h0` для преобразования цветовых данных (через объект `ca` и `k0`).

## 5. Наследник `n0` – переключение между двумя наборами параметров

### 5.1. Дополнительные поля
| Поле | Тип | Назначение |
|------|-----|------------|
| `W` | `int` | Индекс активного под-объекта (0 или 1). |
| `X` | `i0` | Первый набор параметров (например, для B‑режима). |
| `Y` | `i0` | Второй набор параметров (например, для цветного режима). |
| `Z` | `i0` | **Активный** набор параметров (указывает на X или Y). |

### 5.2. Метод `a2(int i4)`
- Устанавливает `W = i4`.
- Выбирает `Z = (i4 == 0) ? X : Y`.
- Копирует из `Z` в текущий объект параметры `f9527g`, `f9683s`, `A` (наследуемые от `x0`).
- Таким образом, при переключении режима все параметры (размеры, матрицы, настройки) заменяются на соответствующие.

### 5.3. Переопределение `y()`
- Возвращает **контроллер `m0`** (а не `w0`, как в `x0`). Это означает, что для устройств, представленных классом `n0` (например, большинство современных сканеров), базовым контроллером становится `m0`, который поддерживает управление мощностью.

### 5.4. Роль в обработке
- Когда контроллер (`m0` или его наследники) запрашивает параметры (например, `w()`, `E()`, `F()`, `G()`), он обращается к полям `f9561c` (типа `p1`), но фактически вызовы переадресуются через методы `n0` к активному `Z`. Таким образом, все параметры берутся из выбранного набора.
- При смене режима (например, с B на цветной) вызывается `a2(1)`, и все последующие запросы используют параметры из `Y`. Это критично, так как цветной режим может иметь другое количество линий, другую частоту и матрицы преобразования.

## 6. Класс `q9` – конкретная реализация для UX‑8C

### 6.1. Конструктор `q9(String str)`
- Если строка начинается с `"UX-8C "`, то:
  - Вызывается `A("UXC")` – устанавливает короткое имя.
  - Извлекается позиция пробела, формируются две строки:
    - `str2 = "UX-8C A" + остаток` (добавляет суффикс "A").
    - `str3 = "UX-8C B" + остаток` (добавляет суффикс "B").
  - Создаются объекты `r9(str2)` и `s9(str3)` (это, скорее всего, наследники `i0` с разными параметрами).
  - Поля `X` и `Y` инициализируются этими объектами.
  - Вызывается `a2(0)` – активируется первый набор (X).

### 6.2. Переопределение `y()`
- Вместо `m0` возвращает **`o0`** – специализированный контроллер для UX‑8C, который, как мы видели ранее, добавляет управление усилителем мощности (PA).
- При создании `o0` копирует из `h0` (полученного из `Z.y()`) поля `f9562d`, `A`, `B`, `J`, устанавливает `f9561c = this` (ссылку на модель), и вызывает `y(this.Z.f9527g.f9535f / 2)` – инициализирует индекс.

### 6.3. Методы `c()` и `k()`
- Оба возвращают `true` – это, вероятно, означает, что устройство поддерживает все режимы и расширенные функции.

### 6.4. Роль в обработке
- `q9` является **фабрикой** для создания правильного контроллера (`o0`) и инициализации двух наборов параметров (`r9` и `s9`). Эти наборы, вероятно, различаются размерами кадра, частотами и матрицами для разных режимов работы (например, один для B‑режима, другой для цветного допплера).
- При переключении режимов (через вызов `B(int)` в контроллере) в конечном счёте вызывается `a2()` на модели, и параметры заменяются. Контроллер при этом обновляет свои внутренние структуры (через `S1()`), используя новые параметры.
- Все запросы к модели (размеры, коэффициенты) идут через `Z` и, следовательно, зависят от активного набора.

## 7. Дополнительные классы (кратко)

### 7.1. `l0` – обработка для специального режима (не для UX‑8C)
Этот класс наследует `g0` (вероятно, ещё один контроллер) и переопределяет методы фильтрации изображения (медианный фильтр, усреднение). Он использует массивы `f9444a0` и `f9445b0` для временного хранения бинарных масок (thresholding) и применяет медианную фильтрацию. Этот класс, скорее всего, используется для устройств с низким качеством сигнала, но не относится к UX‑8C (поскольку `q9` создаёт `o0`, а не `l0`).

### 7.2. `o1` и `z0` – механизмы сохранения
- `o1` – singleton, предоставляющий методы `e()`, `b()`, `i()`, `g()` для чтения/записи целых чисел и булевых значений по ключу (используется для сохранения настроек в SharedPreferences или базе данных).
- `z0` – глобальный объект, позволяющий отправлять изменения параметров на сервер или в UI (через обратные вызовы).

Они используются в модели (`p1`, `x0`) для сохранения пользовательских настроек между запусками приложения.

## 8. Полный процесс обработки данных с участием модели

1. **Инициализация**  
   - При старте приложения создаётся экземпляр `q9` с строкой идентификации `"UX-8C ..."`.
   - В конструкторе создаются два под-объекта (`r9`, `s9`) и активируется первый (`a2(0)`).
   - Модель загружает сохранённые параметры (усиление, зум, глубину, фокус, гармоники и т.д.) через `o1`.

2. **Создание контроллера**  
   - Вызывается `q9.y()`, который создаёт `o0` и связывает его с моделью (`f9561c = this`).
   - Контроллер инициализируется, используя параметры из активного набора (`Z`).

3. **Запуск WiFi‑связи**  
   - Контроллер (`o0`) через `e()` запускает менеджер `s0`, который подключается к устройству.

4. **Передача команд**  
   - При изменении параметров (например, пользователь меняет усиление) контроллер вызывает метод модели (`H()`), который обновляет поле и сохраняет его.
   - В следующем цикле отправки (`a()`) контроллер формирует пакет, используя значения из модели (через `f9561c`). Все размеры, частоты и коэффициенты берутся из `Z`.

5. **Приём данных**  
   - При получении кадра контроллер (`o0` через родительские методы) извлекает из модели размеры (`w()`, `E()`), частоту (`K()`), динамический диапазон и другие метаданные для упаковки в объект `m2.u`. Эти данные также берутся из активного набора (`Z`).

6. **Переключение режимов**  
   - При смене режима (например, переход на цветной допплер) вызывается `B(mode)` в контроллере, который в итоге вызывает `a2(newMode)` на модели.
   - Модель заменяет `Z` на соответствующий набор (`X` или `Y`), и все последующие вызовы используют новые параметры.
   - Контроллер также обновляет свои внутренние структуры через `S1()`.

## 9. Резюме

Иерархия `p1` → `b1` → `x0` → `n0` → `q9` обеспечивает:

- **Хранение параметров** – все настройки устройства, калибровки, размеры кадров, коэффициенты преобразования.
- **Переключение между режимами** – за счёт дублирования параметров в двух наборах (`X` и `Y`) и механизма `a2()`.
- **Сохранение настроек** – через интеграцию с `o1` и `z0`.
- **Генерацию правильного контроллера** – каждый класс переопределяет `y()`, возвращая соответствующий обработчик (`a1`, `w0`, `m0`, `o0`).
- **Адаптацию к конкретному устройству** – `q9` специализируется на UX‑8C, создавая два набора параметров (`r9`, `s9`) и контроллер `o0` с поддержкой PA.

Таким образом, модель является **единым источником истины** для всех параметров, а контроллеры лишь опрашивают её при формировании команд и обработке данных. Это позволяет гибко управлять устройством, сохранять настройки и быстро переключать режимы без изменения логики контроллеров.
