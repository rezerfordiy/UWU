# Доклад: Класс `m0` – управление мощностью и передача данных

## 1. Введение и место в иерархии
Класс `m0` является **прямым наследником `h0`**. Он не добавляет новые режимы визуализации, но вводит **механизм управления мощностью** (Power) и **буферизацию команд переключения режимов**. Его основная задача – генерировать специальные управляющие пакеты, которые позволяют аппаратной части устройства изменять уровень выходной мощности, а также обеспечивать синхронизацию состояния между программным и аппаратным уровнями при смене режимов работы.

В иерархии для устройства **UX‑8C** `m0` является промежуточным звеном перед `o0` (который уже специализируется на цветовых режимах). Без `m0` невозможно корректно управлять мощностью сканирования и передавать в устройство команды переключения между B-режимом, цветным допплером и т.д.

---

## 2. Полный перечень констант и диапазонов

В `m0` используются следующие фиксированные значения:

| Константа / Диапазон | Значение | Назначение |
|----------------------|----------|------------|
| `POWER_PACKET_HEADER` | `{87, 117, 0, 0}` | Заголовок (магическое число) для короткого пакета управления мощностью в обычном режиме (не NT). |
| `POWER_PACKET_HEADER_NT` | `{85, -86, -1, 0, 12, 0, 1, 0, 1, (byte)(power&3), 0, 0}` | Заголовок для пакета управления мощностью в NT‑режиме (12 байт). |
| `POWER_PACKET_SIZE` | `4` или `12` | Размер пакета в зависимости от режима (`s()`). |
| `MAX_POWER_VALUE` | `3` (0–3) | Максимальное значение мощности (передаётся в битах 0–1 байта). |
| `COMMAND_ATTEMPTS` | `5` | Количество попыток отправки команды (сохраняется в `f9452d0`). |
| `CHECKSUM_BYTE_INDEX` | `5` (в NT-пакете) | Индекс байта, куда записывается контрольная сумма. |
| `PREAMBLE_BYTE_0` | `0x55` (85) | Первый байт NT-заголовка. |
| `PREAMBLE_BYTE_1` | `0xAA` (170) | Второй байт NT-заголовка. |
| `PREAMBLE_BYTE_2` | `0xFF` (255) | Третий байт NT-заголовка. |
| `PREAMBLE_BYTE_3` | `0x00` | Четвёртый байт NT-заголовка. |

Также используются константы, унаследованные от `h0` (например, значения режимов 0, 1, 2, 3, 5, 6, 7) – они определяют, как интерпретируется переданное значение мощности в зависимости от текущего режима.

## 3. Поля состояния (добавленные в `m0`)

| Поле | Тип | Назначение |
|------|-----|------------|
| `f9451c0` (обозначим как `modeIndex`) | `int` | Индекс текущего режима, получаемый из входящего пакета (байт 8 в ответе устройства). Используется для синхронизации. |
| `f9452d0` (обозначим как `attemptsLeft`) | `int` | Количество оставшихся попыток отправки команды переключения мощности. Инициализируется в `R1()` и декрементируется при формировании пакета (`M1`/`Q1`). Если достигает 0 – команда считается выполненной и больше не отправляется. |
| `f9453e0` (обозначим как `powerValue`) | `int` | Текущее значение мощности (0–3), которое должно быть отправлено в устройство. |

## 4. Процесс формирования исходящих команд

### 4.1. Основной механизм – метод `O1(int)`

Этот метод является точкой входа для формирования пакета управления мощностью. Он выбирает, какой формат использовать – обычный (`M1`) или NT‑режим (`Q1`), в зависимости от значения `s()` (наследуется от `a1` и показывает, используется ли NT‑протокол).

- Если `s()` возвращает `true`, вызывается `Q1(i4)`, иначе `M1(i4)`.
- Возвращаемый массив байт будет добавлен к общему исходящему потоку.

### 4.2. Формирование пакета в обычном режиме – `M1(int)`

**Условие отправки:**  
Пакет формируется только если `attemptsLeft > 0`. Если попыток нет – возвращается `null`.

**Алгоритм:**
1. Декрементируется `attemptsLeft` (уменьшается на 1).
2. Создаётся массив из 4 байт: `{87, 117, 0, 0}`.
3. В байт с индексом `2` помещается значение `powerValue & 3` (младшие 2 бита).
4. Возвращается этот массив.

**Примечание:** Контрольная сумма не вычисляется – это простой короткий пакет.

### 4.3. Формирование пакета в NT‑режиме – `Q1(int)`

**Условие отправки:**  
Аналогично – только если `attemptsLeft > 0`.

**Алгоритм:**
1. Декрементируется `attemptsLeft`.
2. Создаётся массив из 12 байт с фиксированным заголовком:
   ```
   {85, 170, 255, 0, 12, 0, 1, 0, 1, (byte)(powerValue & 3), 0, 0}
   ```
   - Байт `[9]` содержит значение мощности (младшие 2 бита).
3. Вычисляется контрольная сумма: суммируются все байты с индекса 0 по 11 (кроме байта 5, который пока равен 0). Затем `bArr[5] = (0 - sum) & 0xFF`.
4. Возвращается итоговый массив.

### 4.4. Интеграция в общий пакет – метод `a(int)`

Метод `a(int)` переопределён и вызывает `super.a(i4)`, а затем добавляет результат `O1(i4)` с помощью `r0.t()`. Это означает, что каждый такт (каждый вызов `a()` из внешнего цикла) будет пытаться отправить пакет управления мощностью, пока `attemptsLeft > 0`.

### 4.5. Метод `v(int)`

Этот метод (переопределённый из `r0`) также добавляет `O1(i4)` к данным, возвращаемым `super.v(i4)`. Он используется для отправки данных по запросу из менеджера (например, когда устройство запрашивает параметры).

## 5. Процесс обработки входящих данных

### 5.1. Обработка длинных пакетов – `c(byte[])`

При получении 512‑байтового пакета (вызов `c(byte[])` из `t.a`), `m0` извлекает из байта `[8]` значение режима (`i5 = bArr[8] & 255`) и сравнивает его с текущим `f9451c0`. Если они различаются, вызывается `S1(i5)` для обновления состояния, а также уведомляется `e1` через `e1.z(i5)` (вероятно, для обновления интерфейса).

### 5.2. Обработка коротких управляющих пакетов – `x(byte[])`

При получении пакета, начинающегося с `{90, -91}` (или `{85, 170, 255, 0}` в NT), метод `x(byte[])` (переопределённый из `a1`) проверяет его длину (минимум 4 байта) и, если первые два байта равны `90` и `-91`, извлекает из байта `[2]` значение режима (если установлен бит `0x80` – может быть флагом) и обновляет `f9451c0` аналогичным образом.

**Важно:** В NT-режиме могут приходить другие типы пакетов, но код обрабатывает только указанные.

## 6. Управление мощностью – методы `R1(int)` и `S1(int)`

### 6.1. `R1(int power)`
- Если переданное значение `power` вне диапазона 0–1, метод ничего не делает.
- Иначе устанавливает:
  - `f9452d0 = 5` – количество попыток отправки.
  - `f9453e0 = power` – новое значение мощности.
Это инициирует отправку команд в следующих тактах.

### 6.2. `S1(int mode)`
Этот сложный метод выполняет **синхронизацию состояния** при изменении режима.

**Действия:**
1. Сохраняет новый `mode` в `f9451c0`.
2. Вызывает `((n0) f9561c).a2(mode)` – уведомляет модель `n0` (которая является родителем `p1`) об изменении режима.
3. Получает от модели новый объект `r0` (через `y()`) и обновляет все поля текущего экземпляра (`f9562d`, `A`, `B`, `J`, `C`, `K`, `L` и т.д.) – фактически пересоздаёт настройки для нового режима.
4. Обновляет внутренние структуры `K` и `L` (через вызовы `r()`, `x()`, `w()` и т.д.), чтобы они соответствовали новому режиму.
5. В зависимости от значения `mode` (5, 6, 7) устанавливает флаги в `A` (поле `f9369p` или `A`) для управления доступностью режимов.
6. Вызывает `v0(0)` (выключает гармоники) для некоторых режимов.

Таким образом, `S1` не только меняет значение поля, но и полностью обновляет всё состояние контроллера.

---

## 7. Процесс завершения работы

В `m0` нет отдельного метода `i()` – он наследуется от `h0`, который, в свою очередь, вызывает `super.i()`. При завершении работы достаточно, чтобы родительские классы корректно закрыли соединения.

---

## 8. Резюме по классу `m0`

Класс `m0` выполняет следующие критически важные функции:

- **Управление мощностью** – позволяет изменять уровень выходной мощности устройства (0–3) через отправку коротких или NT-пакетов с контрольной суммой.
- **Буферизация команд** – использует счётчик попыток (`attemptsLeft`), чтобы гарантировать, что команда будет отправлена несколько раз (до 5) для повышения надёжности.
- **Синхронизация состояния** – при смене режима обновляет все внутренние структуры и уведомляет модель, обеспечивая согласованность данных между программным и аппаратным уровнями.
- **Обработка входящих изменений** – при получении ответов от устройства обновляет текущий индекс режима и, при необходимости, инициирует пересинхронизацию.

Все константы (заголовки пакетов, размеры, диапазоны мощности, количество попыток) строго зафиксированы в коде и соответствуют протоколу обмена с ультразвуковым сканером. Без этого класса невозможно корректно управлять мощностью и переключать режимы на устройстве UX‑8C. Следующий уровень – `o0` – добавляет ещё одну степень специализации, связанную с режимом цветового допплера и дополнительными настройками.
