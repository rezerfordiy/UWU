# Доклад: Процесс работы базового контроллера устройства (класс `a1`)

## 1. Введение и место в архитектуре
Класс `a1` является **базовым контроллером** для ультразвукового устройства. Он наследует абстрактный слой `r0` и реализует интерфейс `t.a` (обработчик циклических событий). Его главная задача — управлять **состоянием подключения**, **базовыми параметрами** (усиление, зум) и **обрабатывать сырые потоки данных**, поступающие через WiFi-модуль (`s0`).

Для устройства **UX‑8C** (и аналогичных) `a1` служит фундаментом, но, как мы выяснили ранее, для полной функциональности требуются наследники (`w0`, `h0`, `m0`, `o0`). Однако именно в `a1` заложена **ядро протокола** — отправка команд включения, изменение усиления/зума, а также распаковка базовых B‑режимов.

Ниже приведено детальное описание **всех констант, полей и процессов**, происходящих в этом классе.

## 4. Процесс инициализации и запуска связи (`e()` и `f()`)

1. При вызове `e()` или `f()`:
   - Проверяется наличие менеджера `f9062i`. Если отсутствует — создаётся новый экземпляр `s0(this)` (менеджер WiFi, который мы разбирали ранее).
   - Вызывается `f9062i.j()` — это запускает фоновый поток мониторинга и, если каналы не активны, инициирует подключение к устройству по IP `192.168.1.1` на порты 5002 (управление) и 5003 (данные).

2. Как только WiFi‑канал установлен, менеджер начинает циклически вызывать метод `v(int i4)` из `r0` (который переопределён в `a1`), передавая текущий тактовый счётчик.

## 5. Формирование исходящих команд (метод `a(int)`)

Метод `a(int)` вызывается из внешнего цикла (например, из `s0.l()`) и собирает **композитный пакет** из нескольких возможных команд. Все они объединяются с помощью утилиты `r0.t()` (склейка массивов).

**Составные части пакета:**
1. **Основной пакет состояния** (`M()` или `Q()` в зависимости от `s()`).
2. **Пакет действия** (`P()` или `R()`).
3. **Команда сохранения** (`K()`).
4. **Команда заморозки** (`L()`).
5. **Специальная команда** (`O()`).
6. **Команда обновления** (`N()`).

### 5.1. Основной пакет состояния (`M()` / `Q()`)

**В обычном режиме (`F()`):**
- Формат: `{90, -91, 0, 0}`.
- Байт `[2]` (битовая маска):
  - **Бит 7** (0x80) — включает приём данных (`f9066m = f9063j`).
  - **Бит 5** (0x20) — сбрасывает счётчик повторных попыток (`f9067n`), если он исчерпан.
  - **Биты 0–1** — значение зума (`f9069p`).
- Байт `[3]` — закодированное значение усиления: `(f9068o - 30) * 127 / 75`.

**В NT‑режиме (`Q()`):**
- Формат: `{85, -86, -1, 0, 24, 0, 0, 0, ... 24 байта}`.
- Байт `[5]` — **контрольная сумма** (Checksum). Вычисляется как сумма всех байтов до него, записанная со знаком минус: `checksum = (0 - sum) & 0xFF`.
- Байт `[14]` — счётчик `f9067n`.
- Байт `[15]` — флаг `f9066m` (1 или 0).
- Байт `[16]` — всегда `1`.
- Байт `[17]` — усиление `f9068o`.
- Байт `[18]` — всегда `1`.
- Байт `[19]` — зум `f9069p`.

### 5.2. Пакет действия (`P()` / `R()`)

Если поле `f9070q > 0`, формируется команда выполнения действия.
- **Обычный режим (`G()`):** `{92, -59, CODE, CODE}` — просто дублирует код в байтах 2 и 3.
- **NT‑режим (`R()`):** `{85, 170, 255, 0, 16, 0, 129, 0, CODE, 0, 0, 0, 0, 0, 0, 0}`.
  - Также присутствует контрольная сумма в байте `[5]`.
- После отправки код `f9070q` сбрасывается в `0`.

**Какие коды могут быть установлены внешними методами:**
- Вызов `C(int)` с аргументами `40, 44, 48, 149, 153, 157, 161, 165` или `36` (в NT‑режиме) устанавливает `f9070q`.

### 5.3. Дополнительные управляющие команды

| Команда | Метод формирования | Код в байте `[6]` | Назначение |
|---------|---------------------|-------------------|------------|
| **Сохранение** | `K()` | `130` (0x82) | Сохраняет текущие настройки устройства. Устанавливается через `T(int)`. |
| **Заморозка** | `L()` | `132` (0x84) | Замораживает/размораживает кадр. Устанавливается через `H(boolean)`. |
| **Обновление** | `N()` | `133` (0x85) | Обновляет параметры отображения. Устанавливается через `V(int)`. |
| **Спец. команда** | `O()` | `242` (0xF2) | Специальная команда (например, переключение режима). Устанавливается через `I(boolean)`. |

Все эти команды используют общий формат:  
`{85, 170, 255, 0, 16, 0, CMD, 0, DATA, 0, 0, 0, 0, 0, 0, 0}` и контрольную сумму в байте `[5]`.

## 6. Процесс приёма и обработки данных

Данные от устройства приходят асинхронно через менеджер `s0`, который вызывает методы `w(byte[])` (для управляющего канала) и `x(byte[])` (для канала данных) в `a1`.

### 6.1. Обработка управляющих ответов (`x(byte[])` и `c(byte[])`)

При получении пакета, начинающегося с `{90, -91}`:
- **Байт `[2]`**: если установлен бит 7 (0x80) — включает `f9063j` (приём активен), иначе выключает.
- **Байт `[2]` (биты 0–1)**: извлекается индекс зума `f9065l`.
- **Байт `[3]`**: преобразуется в усиление по формуле: `f9064k = round((b[3] / 127.0) * 75 + 30)`.
- Если состояние приёма изменилось (`z3 != f9063j`), вызывается `S(boolean)` и уведомляется `e1` через `e1.w(z4)`.

При получении 512‑байтового пакета (вызов `c(byte[])`):
- **Байт `[10]` (биты 0–1)**: состояние приёма (включён/выключен).
- **Байт `[11]` (биты 0–6)**: текущее усиление.
- **Байт `[12]`**: индекс зума.
- Аналогично, при изменении состояния отправляется уведомление в `e1`.

### 6.2. Обработка кадров изображения (`w(byte[])` и `b(byte[])`)

Это ключевая часть для отображения B‑режима.

- **Условие приёма**: проверяется флаг `J()`, который возвращает `true`, если приём выключен или идёт синхронизация (`f9067n > 0`). Если приём активен — данные обрабатываются.

- **Формат данных** (`b(byte[])` для полного кадра):
  - Ожидается массив длиной **67725 байт** (129 строк * 525 байт).
  - Цикл по строкам от 1 до 128:
    - Смещение в буфере: `(i4 * 525) + 12` (пропускаем заголовок строки).
    - Копируем 512 байт данных в результирующий массив.
  - Итоговый массив имеет размер `128 * 512 = 65536` байт.

- **Упаковка в объект `m2.u`**:
  - Устанавливаются метаданные: количество линий (`w()`), точек на линию (`E()`), частота (`K()`), глубина, динамический диапазон и т.д.
  - Вызывается `w1.g.y().a(bArr, w, h)` — вероятно, преобразование сырых байт в изображение (например, в RGB или JPEG).
  - Создаётся объект `m2.d0`, в поле `"b_data"` помещается `m2.u`.
  - Если активен специальный режим (`f9564f == 1`), вызывается `m2.w.a(d0Var, k())` для добавления дополнительных данных.
  - Финальный объект передаётся в `e1.v(d0Var)` — это отправляет готовое изображение в пользовательский интерфейс (через Handler).

- **Обработка через `w(byte[])`** (более общий случай):
  - Аналогично, извлекаются данные через `f9562d.h()` и `f9562d.i()` (парсер входящего потока).
  - Также упаковываются в `m2.u` и отправляются в `e1`.

## 7. Управление параметрами (Gain, Zoom, Freeze)

| Действие | Метод в `a1` | Процесс |
|----------|--------------|---------|
| **Увеличение усиления** | `o()` | Если `f9068o < 105`, инкрементирует на 1. Вызывает `f9561c.H(f9068o)` (обновляет модель). |
| **Уменьшение усиления** | `g()` | Если `f9068o > 30`, декрементирует на 1. |
| **Установка усиления** | `z(int)` | Проверяет диапазон (30–105), устанавливает `f9068o`. |
| **Увеличение зума** | `p()` | Инкрементирует `f9065l` и вызывает `D(f9065l)` (проверяет 0–3). |
| **Уменьшение зума** | `h()` | Декрементирует `f9065l`. |
| **Установка зума** | `D(int)` | Ограничивает значение 0–3, устанавливает `f9069p`. |
| **Включение приёма** | `A(true)` / `E()` | Устанавливает `f9066m = true`, сбрасывает счётчик `f9067n = 8`. |
| **Выключение приёма** | `A(false)` | Устанавливает `f9066m = false`. |
| **Заморозка кадра** | `H(boolean)` | В NT‑режиме устанавливает `f9074u` и флаг `f9075v = true` (команда будет отправлена в следующем цикле). |
| **Сохранение** | `T(int)` | Устанавливает `f9078y = i4` и флаг `f9079z = true`. |

## 8. Процесс завершения работы (`i()`)

При вызове `i()` (например, при закрытии приложения):
- Вызывается `super.i()`.
- У менеджера `f9062i` вызывается `k()` — это останавливает потоки мониторинга, закрывает сокеты и освобождает ресурсы.

## 9. Резюме по классу `a1`

Класс `a1` выполняет роль **командного интерпретатора** и **маршрутизатора данных**:
- Он управляет **жизненным циклом WiFi‑соединения**.
- Он **буферизирует команды** (усиление, зум, заморозка, сохранение) и отправляет их в виде структурированных пакетов с контрольными суммами.
- Он **принимает сырые кадры**, выделяет из них изображение (512 байт на строку) и передаёт в бизнес-слой для визуализации.
- Все числовые константы (диапазоны 30–105, 0–3, магические байты 0x55, 0xAA, 0xFF, 0x5A, 0xA5 и т.д.) строго фиксированы и соответствуют протоколу устройства.

Без этого класса невозможен даже базовый обмен данными. Все наследники (`w0`, `h0` и т.д.) лишь **дополняют** этот функционал спецификой цветовых и допплеровских режимов, но ядро протокола остаётся именно в `a1`.
