# Доклад: Класс `w0` – расширенный контроллер для цветовых и допплеровских режимов

## 1. Введение и место в иерархии
Класс `w0` является **прямым наследником** `a1`. Он добавляет поддержку:
- **Режимов визуализации** (B‑режим, цветовой допплер (CFM), энергетический допплер (PDI), гармоники (HI), тканевая гармоника (THI) и др.)
- **Управления параметрами сканирования**: фокус, глубина, количество линий, стееринг (угол наклона), усиление по глубине (TGC), динамический диапазон, частота и т.д.
- **Формирования сложных управляющих пакетов** (с использованием контрольных сумм) для отправки этих параметров на устройство.
- **Обработки расширенных данных** (цветовые карты, допплеровские спектры и пр.).

Вся логика сосредоточена в переопределённых методах `a()`, `b()`, `w()`, `x()`, `c()` и множестве дополнительных методов для настройки. `w0` работает в тесной связке с объектом `x0` (который является наследником `p1` и представляет модель устройства) – через него получает актуальные значения параметров.

## 2. Полный перечень констант (добавленных или переопределённых)

В `w0` используются следующие фиксированные значения (некоторые заданы в классе `x0` и его внутренних структурах, но здесь мы перечисляем используемые в `w0`):

| Константа / Диапазон | Значение | Назначение |
|----------------------|----------|------------|
| `PREAMBLE_EXT` (часть) | `{85, 170, 255, 0, 24, 0}` | Заголовок для 24‑байтового расширенного пакета параметров (используется в `k0()`). |
| `PREAMBLE_ENH` | `{94, -27}` | Заголовок для пакета усиления (enhancement), используется в `j0()`. |
| `PREAMBLE_ENH_SIZE` | `16` байт | Полный размер пакета усиления. |
| `PREAMBLE_EXT_SIZE` | `24` байта | Полный размер расширенного пакета параметров. |
| `CHECKSUM_BYTE_INDEX` | `5` (в 24‑байтовом пакете) | Индекс байта, куда записывается контрольная сумма. |
| `LINE_COUNT_DEFAULT` | 128 | Количество строк в кадре. |
| `SAMPLE_COUNT_DEFAULT` | 512 | Количество точек на строку. |
| `GAIN_STEPS` | 101 (0–100) | Диапазон значений усиления в процентах для TGC и других настроек. |
| `FOCUS_MIN` / `FOCUS_MAX` | зависят от `x0` | Диапазон положения фокуса (определяется через метод `w()` устройства). |
| `LINE_START_MIN` / `LINE_END_MAX` | вычисляются динамически | Ограничения на начальную и конечную линии при выборе области интереса (ROI). |
| `ANGLE_MIN` / `ANGLE_MAX` | 0–3 (для стееринга) | Угол наклона (0–3). |
| `DYNAMIC_RANGE_MIN` / `MAX` | 0–100 (проценты) | Динамический диапазон. |
| `PRF_MIN` / `MAX` | зависит от режима | Частота повторения импульсов (PRF) в кГц. |

Также в коде встречаются магические числа, используемые как маркеры в командах:
- `0x5A, 0xA5` – заголовок короткого пакета (уже были в `a1`).
- `0x55, 0xAA, 0xFF, 0x00` – расширенный заголовок для NT‑режима.
- `0x5E, 0xE5` – заголовок для пакета усиления (`j0()`).

## 3. Поля (добавленные в `w0`)

К полям, унаследованным от `a1`, `w0` добавляет:

| Поле | Тип | Назначение |
|------|-----|------------|
| `A` | `ca` | Объект, вероятно, для постобработки данных (например, коррекция цветовой карты). |
| `B` | `k0` | Объект для обработки допплеровских данных (фильтрация, спектр). |
| `E` | `boolean` | Флаг, указывающий, что были изменены параметры усиления (enhancement) – нужен для отправки обновлённого пакета. |
| `F` | `int` | Значение усиления (enhancement) – используется в `p0()` и `Z()`. |
| `H` | `float` | Параметр частоты (не используется в явном виде). |
| `I` | `int` | Индекс частоты (вероятно, для выбора частоты из списка). |
| `G` | `int` | Счётчик или индекс (используется в `q0`). |
| `C` | `k` | Объект для хранения текущих настроек режима (гармоника, фокус, линии и т.д.). |
| `D` | `a` (внутренний класс) | Хранит массив из 8 целых чисел (`f9666c`) и два байта (`f9667d`) – используются для установки усиления по каналам (enhancement). |

## 4. Процесс инициализации и активации (`d(boolean)` и `u(boolean)`)

При первом включении или восстановлении связи:
- Вызывается метод `d(true)` (из интерфейса `t.a`) или `u(true)` (из `r0`).
- `d(true)` считывает из модели `x0` текущие параметры: 
  - Состояние гармоник (`Q()`), 
  - Усиление (`N()`), 
  - Фокус (`P()`), 
  - Глубину (`O()`), 
  - Режим компундинга (`M()`), 
  - Значения усиления по 8 каналам (`R(i)`).
- Затем вызывает соответствующие сеттеры (`v0()`, `o0()`, `s0()`, `p0()`, `n0()`, `w0()`), которые сохраняют значения в полях `C` и `D`, а также уведомляют модель `x0` через её методы (`j0()`, `l0()`, `m0()`, `n0()`, `o0()`, `p0()`). Это гарантирует синхронизацию состояния.
- В `u(true)` аналогично, но также проверяет, изменился ли какой‑то параметр, и при необходимости отправляет команды.

Таким образом, при активации `w0` загружает последние известные настройки устройства и готовит их к отправке.

## 5. Формирование исходящих команд (метод `a(int)`)

Метод `a(int)` переопределён для добавления дополнительных пакетов, специфичных для режимов.

**Составные части (в порядке вызова):**
1. `super.a(i4)` – вызывает родительский `a()`, который собирает базовые команды (усиление, зум, включение и т.д.).
2. `k0(i4)` – формирует расширенный пакет параметров (усиление по каналам, частота и др.) – только если `E == true` и срабатывает по условию `i4 % 10 == 0`.
3. `j0(i4)` – формирует пакет усиления (enhancement) – также по условию `i4 % 10 == 0` и `E == true`.
4. `i0(i4)` – формирует пакет управления режимом (гармоники, фокус и пр.) – по условию `i4 % 4 == 0` и `s()` (NT‑режим).

Все эти пакеты объединяются с помощью `r0.t()`.

### 5.1. Расширенный пакет параметров (`k0()`)

- Формат (24 байта):  
  `{85, 170, 255, 0, 24, 0, 0x81, 0, ENH[0..7], 0,0,0,0,0,0,0,0}`  
  (начиная с байта 8 – 8 байт усиления по каналам).
- Контрольная сумма вычисляется как сумма всех байтов до позиции 5, затем `b[5] = (0 - sum) & 0xFF`.
- После отправки флаг `E` сбрасывается в `false`.

### 5.2. Пакет усиления (`j0()`)

- Формат (16 байт):  
  `{94, -27, A.f9664a, A.f9665b, ENH[0..7], 0,0}`  
  где `A` – объект внутреннего класса `a`, содержащий дополнительные управляющие байты.
- Этот пакет отправляется независимо от контрольной суммы, но тоже по условию `E`.

### 5.3. Пакет управления режимом (`i0()`)

- Если включён NT‑режим (`s()`), вызывается `this.C.k()` или `this.C.j()`, которые возвращают байтовый массив, содержащий настройки режима (гармоники, фокус, количество линий и т.д.).
- Эти данные добавляются в общий пакет.

## 6. Обработка входящих данных (переопределения `b()`, `w()`, `x()`, `c()`)

### 6.1. Обработка через `b(byte[])` (полные кадры)

Вызывается при получении полного кадра изображения (обычно через управляющий канал).
- Проверяется флаг `J()` (как в `a1`).
- Извлекаются сырые данные через `f9562d.h()` (получает массив изображения) и, если присутствует, через `f9562d.i()` (дополнительные данные, например, цветовая карта).
- Если определён объект `A` (`ca`), то данные пропускаются через `A.a()` – возможно, для цветокоррекции.
- Если определён объект `B` (`k0`), проверяется наличие флагов в байте `bD = f9562d.d()`:
  - Если `(bD & 8) != 0` – вызывается `B.e(данные, параметр, индекс)` – вероятно, фильтрация или обработка спектра.
  - Если `(bD & 128) != 0` – вызывается `B.f(данные, параметр, индекс)` – аналогично.
- Затем создаётся объект `m2.u` для хранения изображения и метаданных (размеры, частота, динамический диапазон, значения усиления и т.д.).
- Вызывается `w1.g.y().a(bArr, width, height)` для преобразования в изображение.
- Упаковывается в `m2.d0` и отправляется в `e1.v(d0Var)`.

### 6.2. Обработка через `w(byte[])` (для управляющего канала)

Аналогично `b()`, но данные извлекаются через `f9562d.h()` и `f9562d.i()`.
- Если активен объект `B`, проверяется наличие допплеровских данных и обрабатывается через `B.e()` или `B.g()`.
- Если `B.e()` возвращает `null`, данные могут быть изменены или отброшены.
- Если `bArrH` (изображение) не `null`, он упаковывается в `m2.u` аналогично.

### 6.3. Обработка управляющих ответов (`x(byte[])` и `c(byte[])`)

- `x(byte[])` вызывается для коротких пакетов (`{90, -91}`). Здесь дополнительно обрабатывается:
  - Байт `[2]` – если установлен бит 7, включает приём, иначе выключает.
  - Байт `[3]` – извлекается усиление.
- `c(byte[])` обрабатывает пакеты длиной 512 байт. Из них извлекаются:
  - Байт `[10]` (биты 0‑1) – состояние приёма.
  - Байт `[11]` – усиление.
  - Байт `[12]` – зум.
  - Также может быть обработан пакет сохранения (если внутри есть маркер `0x55, 0xAA, 0xFF, 0x00`), который при получении генерирует уведомление в `e1.y()`.

## 7. Управление параметрами (методы для установки)

Класс `w0` предоставляет множество методов для изменения параметров. Все они изменяют внутренние поля (`C`, `D`, `F`, `G` и т.д.) и флаг `E`, а также уведомляют модель `x0`.

### 7.1. Управление гармониками (`v0(boolean)`)
- Устанавливает состояние гармоник в `C` (байт 0 или 1).
- Вызывает `x0().o0(z3)`.
- Влияет на формирование пакетов режима.

### 7.2. Управление фокусом (`s0(int)`)
- Устанавливает значение фокуса (0–3) в `C`.
- Вызывает `x0().n0(i4)`.

### 7.3. Управление глубиной (`p0(int)`)
- Устанавливает глубину (индекс) в `F`.
- Вызывает `x0().m0(i4)`.

### 7.4. Управление линиями (`o0(int)`)
- Устанавливает количество линий (индекс) в `C`.
- Вызывает `x0().l0(i4)`.

### 7.5. Управление компундингом (`n0(boolean)`)
- Включает/выключает режим компундинга (усреднение кадров) в `C`.
- Вызывает `x0().k0(z3)`.

### 7.6. Управление усилением по каналам (`w0(int, int)`)
- Устанавливает значение для одного из 8 каналов в массиве `D.f9666c`.
- Устанавливает флаг `E = true`.
- Вызывает `x0().p0(i4, i5)`.

### 7.7. Управление мощностью (l0(int) и m0(...))
- `l0(int)` – устанавливает значение мощности (0–100) в `C`.
- `m0(boolean, float, int)` – управляет параметром частоты и усилением, с проверкой допустимых значений.

### 7.8. Управление стеерингом (`r0(int)` и `t0(int)`)
- Устанавливают значения стееринга (угол) в `C`.

## 8. Процесс завершения работы

При вызове `i()` (через `super.i()`) – просто вызывает родительский, который останавливает WiFi‑менеджер. Никаких дополнительных действий не требуется, так как все поля локальны и будут уничтожены сборщиком мусора.

---

## 9. Резюме по классу `w0`

Класс `w0` значительно расширяет возможности `a1`, добавляя:
- Поддержку нескольких режимов визуализации.
- Настройку множества параметров сканирования.
- Формирование дополнительных управляющих пакетов с контрольными суммами.
- Обработку сложных входящих данных (цветовой допплер, спектры).
- Синхронизацию состояния с моделью `x0`.

Все константы (диапазоны значений, магические байты, размеры пакетов) жёстко заданы и соответствуют протоколу устройства. Без этого класса невозможно работать с цветными или допплеровскими режимами. Следующий уровень – `h0` – добавляет ещё более тонкую настройку для цветовых режимов (работа с цветовой картой, динамическим диапазоном и т.п.).
