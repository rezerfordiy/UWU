# Доклад: Класс `h0` – управление цветовым и энергетическим допплером (CFM/PDI/PW)

## 1. Введение и место в иерархии
Класс `h0` является **прямым наследником `w0`** и представляет собой специализированный контроллер для работы с **цветовыми режимами** и **спектральными допплеровскими режимами**. В то время как `w0` отвечал за общие параметры сканирования и базовые режимы, `h0` берёт на себя управление:

- **Цветовым допплером (CFM)** – отображение скорости кровотока в цвете.
- **Энергетическим допплером (PDI)** – отображение мощности кровотока.
- **Спектральным допплером (PW)** – отображение спектра скоростей в реальном времени.
- **Дополнительными настройками B‑режима** (например, угол стееринга, динамический диапазон, положение фокуса) – но уже в контексте совмещённых режимов (B+Color, B+Power).

Для устройства **UX‑8C** именно `h0` (через своего наследника `m0` и далее `o0`) обеспечивает полноценную работу всех диагностических режимов.

---

## 2. Полный перечень констант (добавленных или переопределённых)

Класс `h0` вводит **константы режимов**, которые используются для маршрутизации внутри системы:

| Константа | Значение | Назначение (режим работы) |
|-----------|----------|---------------------------|
| `W` | `0` | **Только B‑режим** (базовый, без наложения цвета). |
| `X` | `2` | **B + Цветовой допплер (CFM)** – наложение цветного потока на B‑режим. |
| `Y` | `3` | **B + Энергетический допплер (PDI)** – наложение энергетического потока. |
| `Z` | `0` | Дублирует `W` (устаревшее). |
| `f9330a0` | `1` | Вспомогательная константа (используется в `S1`). |
| `T` | `5` | **Полноэкранный цветовой допплер** (CFM без B‑фона). |
| `U` | `6` | **Полноэкранный энергетический допплер** (PDI без B‑фона). |
| `V` | `7` | **Спектральный допплер (PW)** – отображение спектра. |

Также используются **диапазоны и пределы** (вычисляемые динамически через `x0`):
- `w()` – количество линий в B‑кадре (обычно 128).
- `E()` – количество точек в линии (обычно 512).
- `A.f9361h` – минимальная ширина области интереса (ROI) для цвета.
- `A.f9362i` – максимальная ширина ROI.
- `T0()` – максимальное количество позиций фокуса.
- `e1()` – количество точек в цветовой карте.
- `h1()` – количество доступных значений усиления.

## 3. Поля состояния (добавленные в `h0`)

| Поле | Тип | Назначение |
|------|-----|------------|
| `J` | `f` | Объект, управляющий параметрами **упрощения/фильтрации** (упрощение B‑режима, тёмный пропуск и т.д.). |
| `K` | `e` | **Параметры цветового B‑режима** (Color B‑mode) – хранит настройки, связанные с цветовым окном, стеерингом, позицией линий. |
| `L` | `g` | **Параметры цветового допплера** (Color Doppler) – хранит настройки PRF, динамического диапазона, усиления, угла и т.д. |
| `M` | `int` | Тип режима (см. константы выше) – используется для отправки в устройство. |
| `N` | `int` | Количество линий для цветового окна (ROI). |
| `O` | `int` | Счётчик для анимации зума (используется для плавного переключения). |
| `P` | `int` | Текущее значение усиления (синхронизируется с устройством). |
| `Q` | `int` | Целевое значение усиления (используется для сглаживания изменения). |
| `R` | `int` | Счётчик для анимации переключения режимов. |
| `S` | `int` | Текущий индекс режима (0–3), используемый для отправки в `m1`. |

## 4. Процесс переключения режимов (`B(int)`)

Метод `B(int)` устанавливает режим работы устройства и является **центральным** в `h0`.

**Логика (упрощённо):**
- Если `mode == 0` → B‑режим.
- Если `mode == 1` → B+Color (устанавливает `M = 0`).
- Если `mode == 5` → Полноэкранный цвет (устанавливает `M = 2`, `N = 0`).
- Если `mode == 6` → Полноэкранный энергетический (устанавливает `M = 2`, `N = 1`).
- Если `mode == 7` → Спектральный (устанавливает `M = 3`).

После изменения режима:
- Вызывается `v0(false)` (отключает гармоники, если нужно).
- Вызывается `m0(false, 0.0f, 0)` (сбрасывает усиление).
- Вызывается `S(boolean)` и `u(boolean)` для обновления состояния.
- Если режим `5` или `6`, проверяются флаги `A.f9369p` (возможность цветового режима) и `A.A` (возможность спектрального).

**Важно:** В этом методе также определяются `M` и `N`, которые используются при формировании исходящих пакетов (`m1()`).

## 5. Формирование исходящих команд (методы `a()`, `f1()`, `g1()`, `m1()`, `y0()`)

### 5.1. Метод `a(int)`
Переопределён, чтобы добавить два специализированных пакета:
- `f1(i4)` – формирует пакет параметров для **B‑режима с цветом** (управляется объектом `K`).
- `g1(i4)` – формирует пакет параметров для **цветового допплера** (управляется объектом `L`).

Оба вызываются с условием `i4 % 5 == 0` и используют `K.a()` / `L.a()` для формирования байтовых массивов.

### 5.2. Метод `f1()` и `g1()`
- Проверяют флаг `F1()` – если он `true`, то в `K`/`L` передаётся **количество линий**, иначе `0`.
- Вызывают `K.m()` / `K.l()` или `L.m()` / `L.l()` для получения байтового массива.
- Возвращают `null`, если `i4` не кратен 5.

### 5.3. Метод `m1(int)` – формирование основного пакета состояния
Это критический метод, который модифицирует байтовый массив, возвращаемый `super.M(i4)` (из `a1`), добавляя информацию о режиме и позиции.

**Изменяемые байты:**
- **Байт 12** – всегда устанавливается в `1` (идентификатор пакета).
- **Байт 13** – кодирует **тип режима** (`M`):
  - Если режим B или B+Color → `0`.
  - Если полноэкранный цвет → `1`.
  - Если полноэкранный энергетический → `2`.
  - Если спектральный → `3`.
- **Байт 16** – счётчик анимации зума (`O`).
- **Байт 17** – текущее значение усиления (`P`).
- **Байт 18** – счётчик анимации переключения режимов (`R`).
- **Байт 19** – текущий индекс режима (`S`).

Затем вычисляется **контрольная сумма** (сумма всех байтов до позиции 5, записанная со знаком минус) и помещается в байт 5.

### 5.4. Метод `y0(int)` – альтернативное формирование пакета (для не‑NT)
Аналогичен `m1`, но использует другой формат заголовка. Здесь:
- **Байт 2** – устанавливает биты режима (0, 1, 2, 3) и индекс `S`.
- **Байт 3** – кодирует усиление и флаг зума (старший бит устанавливается, если анимация ещё не завершена).
- **Байт 12** – всегда `1`.
- **Байт 13** – кодирует `M` (0,1,2,3).

## 6. Обработка входящих данных (методы `b()`, `w()`)

Основная задача – распознать, какой режим активен, и соответственно извлечь цветовые/допплеровские данные из потока.

### 6.1. Обработка в `b(byte[])` (полный кадр)
- Проверяется состояние (`J()`).
- Из `f9562d` извлекаются: `bArrH` (данные изображения) и `bArrI` (дополнительные данные, если есть).
- Если присутствует объект `A` (`ca`), данные пропускаются через `A.b()` или `A.a()`.
- Если присутствует объект `B` (`k0`), проверяется флаг `(bD & 128) != 0` – если да, вызывается `B.g()` для обработки спектра.
- Затем проверяется **текущий режим** (`m()`):
  - Если `5` (полноэкранный цвет) → вызывается `h1(bArrI, bArrH)` – создаёт объект `m2.y` (цветовые данные) и помещает в `d0Var`.
  - Если `6` (полноэкранный энергетический) → вызывается `j1(bArrI, bArrH)` – создаёт `m2.c0` (энергетические данные).
  - Если `7` (спектральный) → вызывается `i1(bArrI)` – создаёт `m2.b0` (спектр).

**Важно:** Для режимов 5 и 6 автоматически корректируется область интереса (ROI) с помощью `u1()` – она выравнивается по центру, чтобы не выходить за пределы допустимых значений.

### 6.2. Обработка в `w(byte[])` (управляющий канал)
Аналогична `b()`, но дополнительно:
- Проверяется флаг `(bD & 128) != 0` – если да, извлекается параметр `iW = L1().W(L1().K0(bD))` и передаётся в `B.g()`.
- Если данные отфильтрованы и превращены в `null`, обработка прерывается.
- Для режимов 5 и 6 также вызывается `u1()` для автоматической коррекции ROI.

### 6.3. Специальная обработка сигнала «Сохранить»
В `l1(byte[])` (и `k1`) ищется последовательность `0x55 0xAA 0xFF 0x00` во входящем потоке. При обнаружении:
- Создаётся JSON `{"SAVE_BUTTON": "CLICKED"}`.
- Отправляется через `e1.y(json.toString())` – вероятно, для отображения уведомления в интерфейсе.

## 7. Управление параметрами цвета и допплера

Множество методов позволяют настраивать цветовой и допплеровский режим:

| Метод | Параметр | Назначение |
|-------|----------|------------|
| `B1(int)` | 0–100 | Устанавливает **угол стееринга** (PRF-угол) для B‑режима в объект `L`. |
| `C1(int)` | 0–100 | Устанавливает **динамический диапазон** для цветового режима. |
| `D1(int)` | 0–3 | Устанавливает **положение фокуса** для цвета. |
| `E1(int)` | 0–100 | Устанавливает **усиление** цвета. |
| `F1(int)` | 0..`w()`-1 | Устанавливает **позицию линии** для цвета. |
| `G1(int)` | 20..(`E()`-1-16) | Устанавливает **начальную точку ROI**. |
| `H1(int)` | `20`..`E()-17` | Устанавливает **начало ROI** (границы) для B‑режима. |
| `I1(int)` | 0..`e1()` | Устанавливает **индекс стееринга** (угол поворота сканирования). |
| `J1(int)` | 0..`h1()` | Устанавливает **индекс объёма** (volume index) для цветового режима. |

Все эти методы изменяют соответствующие поля в объектах `K` и `L`, а также вызывают методы модели `L1()` (которая является `i0`) для синхронизации состояния.

---

## 8. Процесс завершения работы и сброса

В `h0` нет отдельного метода `i()` – он наследуется от `w0` (который, в свою очередь, вызывает `super.i()`). Однако метод `r1(boolean, int)` и `y1(boolean)` позволяют включать/выключать **упрощение B‑режима** (dark pass filter, simplify). При изменении этих параметров формируется JSON-команда, которая отправляется через `z0.a()` в модель для сохранения.

## 9. Резюме по классу `h0`

Класс `h0` является **ключевым звеном** для работы с цветовыми и спектральными режимами в устройстве UX‑8C:

- Он **переключает режимы** (B, B+Color, PDI, PW) и кодирует их в исходящие пакеты.
- Он **управляет ROI** (областью интереса) для цветовых режимов, автоматически корректируя её размеры при получении данных.
- Он **обрабатывает входящие данные**, разделяя их на B‑изображение и цветовую/допплеровскую накладку, а также извлекает спектральные данные.
- Он предоставляет **тонкие настройки** (усиление цвета, динамический диапазон, PRF, угол и т.д.), которые сохраняются в объектах `K` и `L` и отправляются в виде структурированных пакетов с контрольной суммой.
- Он **детектирует события сохранения** (нажатие кнопки на устройстве) и передаёт их в UI.

Все константы (режимы `0, 1, 2, 3, 5, 6, 7`, диапазоны 0–100, 0–3, границы ROI, магические байты `0x55, 0xAA, 0xFF, 0x00`) жёстко зафиксированы в коде и соответствуют протоколу обмена с ультразвуковым сканером. Следующий уровень – `m0` – добавляет специфику управления мощностью и передачей данных в режиме реального времени.
