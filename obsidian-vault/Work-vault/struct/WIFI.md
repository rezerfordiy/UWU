k2.b2.java
---
Это **сетевой менеджер Wi-Fi** — ключевой класс для обнаружения и подключения к физическому прибору! Давай разберем его детально.

## Что делает этот класс

Это синглтон (паттерн `n(Context)`), который управляет **поиском и подключением к ультразвуковому прибору** по Wi-Fi.

---

## Архитектура класса

### 1. Режимы работы (константы `f8366i` / `f8367j`)

```java
f8366i = 1  // MODE_AP (прибор как точка доступа)
f8367j = 2  // MODE_STA (прибор как клиент в общей сети)
```

Эти режимы возвращаются через колбэк `InterfaceC0071b.a(int)`:
- `1` — нашли прибор в режиме точки доступа
- `2` — нашли прибор в локальной сети

### 2. Списки устройств

```java
List f8371b  // "белый список" — известные приборы
List f8372c  // "чёрный список" — игнорируемые устройства
```

Устанавливаются методами `r(List)` и `q(List)`.

### 3. Внутренние потоки

**`d` (Discovery Thread)** — поток обнаружения:
- Работает с интервалом 1 секунда
- Проверяет текущий Wi-Fi SSID через `o2.b` и системный `WifiManager`
- Если SSID совпадает с "белым списком" → колбэк `1` (режим AP)
- Если SSID в "чёрном списке" → колбэк `2` (режим STA)

**`c` (Receiver Thread)** — поток приёма UDP-пакетов:
- Открывает `DatagramSocket` на порту **52012**
- Принимает broadcast-пакеты от прибора
- Парсит идентификационную информацию
- Если пакетов нет > ~3 секунд — сбрасывает найденные имена

## Протокол обнаружения — самое интересное!

Метод `p(byte[] bArr)` парсит пакеты от прибора. Вот структура протокола:

### Формат пакета обнаружения:

```
Байты 0-3:  Заголовок (0x55, 0xAA, 0xFF, 0x00) — синхросигнал
Байт 7:     Тип сообщения
            0x00 → пакет обнаружения (discovery)
            0x80 → ответ на запрос
            0x81 → объявление прибора
Байты 8-63: Информация о приборе
```

### Для типа 0x00 (Discovery Response):
```
[0-15]  байты 16-31 → имя устройства (SSID)
[16-31] байты 32-47 → IP-адрес прибора
[32-47] байты 48-63 → версия ПО (сохраняется в f8377h)
[48-79] байты 64-95 → серийный номер (сохраняется в f8376g)
```

### Для типа 0x80/0x81 (Announce):
```
[0-15]  байты 16-31 → версия ПО (f8377h)
[16-39] байты 32-55 → имя/серийный номер (f8376g)
```

## Пример работы протокола

### Прибор включает Wi-Fi AP:
```
1. Телефон подключается к Wi-Fi сети "Sonoptek_XX"
2. Поток d обнаруживает SSID в белом списке → колбэк 1
3. Поток c получает UDP пакет на порт 52012:
   55 AA FF 00 00 00 00 00  [заголовок + тип 0]
   "SL-2C..........."       [модель датчика]
   "192.168.1.100.."        [IP прибора]
   "v2.1.3.........."       [версия ПО]
   "SN2024001......."       [серийный номер]
4. Сохраняет: f8376g = "SN2024001", f8377h = "v2.1.3"
```

### Прибор в локальной сети:
```
1. Телефон в любой Wi-Fi сети
2. Прибор отправляет broadcast UDP пакет типа 0x81
3. Телефон получает и парсит модель + серийный номер
4. Приложение показывает прибор в списке доступных
```

## Итог

Этот класс — **первое звено** в цепочке:
1. **Обнаруживает** прибор по Wi-Fi (UDP broadcast + SSID)
2. **Идентифицирует** модель и версию ПО
3. **Оповещает** UI о статусе подключения
4. **Передаёт** IP/серийный номер движкам `e1`/`z1.c1` для открытия TCP-канала передачи данных

Следующий шаг после обнаружения — ищи классы, которые открывают TCP-сокет для приёма потока A-сканов (скорее всего в `n2.e1` или `z1.c1`).

## Источники информации о SSID

### 1. Прямое указание в коде — метод `p()`

В методе `p(byte[] bArr)` есть парсинг байтового массива:

```java
// Тип 0x00 (Discovery Response):
byte[] bArr2 = new byte[16];
System.arraycopy(bArr, 16, bArr2, 0, 16);
i(bArr2);  // ← это имя устройства (SSID)

byte[] bArr3 = new byte[16];
System.arraycopy(bArr, 32, bArr3, 0, 16);
i(bArr3);  // ← IP-адрес
```

Метод `i(byte[])` конвертирует байты в строку:
```java
public final String i(byte[] bArr) {
    StringBuilder sb = new StringBuilder();
    for (byte b4 : bArr) {
        if (b4 != 0) {
            sb.append((char) b4);  // байты → символы
        }
    }
    return sb.toString();
}
```

**Вывод:** Прибор отправляет своё имя (SSID) внутри UDP-пакета.

### 2. Системный Wi-Fi — метод `l()`

```java
public final String l() {
    return ((WifiManager) context.getSystemService("wifi"))
        .getConnectionInfo()
        .getSSID()
        .replace("\"", "");  // убирает кавычки
}
```

Это прямое чтение SSID сети, к которой подключён телефон.

### 3. Библиотека `o2.b` — метод `j()`

```java
b.a aVarH = o2.b.g(context).h();
String strJ2 = aVarH != null ? o2.b.j() : null;
```

Здесь используется обфусцированная библиотека `o2.b` — вероятно, хелпер для сканирования Wi-Fi сетей.

## Полная цепочка обнаружения

```
1. Телефон сканирует Wi-Fi сети
   ↓ WifiManager.getScanResults()
   
2. o2.b библиотека фильтрует сети
   ↓
   
3. Находит сеть, совпадающую с паттерном из f8371b (белый список)
   ↓
   
4. Читает SSID напрямую через WifiManager.getConnectionInfo().getSSID()
   ↓
   
5. Параллельно слушает UDP broadcast на порту 52012
   ↓
   
6. Парсит имя прибора из байтового пакета (байты 16-31)
   ↓
   
7. Сравнивает с белым/чёрным списками
   ↓
   
8. Вызывает колбэк с режимом (1=AP, 2=STA)
```

Это и есть **разрешённые модели приборов** для подключения.

## `o2.b.java` — это **USB-менеджер** приложения!

Класс управляет **подключением к прибору через USB** (альтернатива Wi-Fi). Теперь полная картина проясняется: прибор можно подключить **двумя способами** — по Wi-Fi (`k2.b`) или по USB (`o2.b`).

---

## Структура класса

### Внутренние классы

| Класс | Назначение |
|-------|------------|
| `a` | Данные подключения: `UsbDevice`, `UsbDeviceConnection`, идентификатор |
| `InterfaceC0091b` | Колбэки: `c()` — устройство отключено, `d()` — устройство подключено |
| `c` | `BroadcastReceiver` — слушает системные события USB (`ATTACHED`/`DETACHED`) |
| `d` | Фильтр устройств: `vendorId` + `productId` |

### Поля

```java
Map<String, UsbDevice> f9928b     // список USB-устройств в системе
UsbManager f9929c                  // системный USB-менеджер
a f9930d                           // текущее активное подключение
List<d> f9931e                     // белый список (нужные VID/PID)
String f9932f                      // идентификатор выбранного устройства
PendingIntent f9936j              // запрос разрешения на USB
List<InterfaceC0091b> f9937k      // слушатели подключения/отключения
```

## Основные методы

### 1. `m()` — сканирование USB-устройств
```java
public int m() {
    UsbManager usbManager = (UsbManager) context.getSystemService("usb");
    HashMap<String, UsbDevice> deviceList = usbManager.getDeviceList();
    this.f9928b = deviceList;
    return deviceList.size();  // сколько устройств найдено
}
```

### 2. `c(String)` — подключение к конкретному устройству
```java
public boolean c(String str) {
    // 1. Ищет устройство по ключу в Map
    // 2. Проверяет разрешение (hasPermission)
    // 3. Если нет — запрашивает (requestPermission)
    // 4. Если есть — открывает UsbDeviceConnection
    // 5. Сохраняет в f9930d
}
```

### 3. `h()` — авто-подключение (возвращает текущее соединение)
```java
public a h() {
    // 1. Сканирует USB-устройства (m())
    // 2. Если уже подключены → возвращает f9930d
    // 3. Если есть сохранённый ID → подключается к нему
    // 4. Если авто-подключение разрешено (f9933g):
    //    - Перебирает все USB-устройства
    //    - Сверяет VID/PID с белым списком f9931e
    //    - Подключается к первому совпавшему
}
```

### 4. Статические методы — `j()` и `k()` (чтение данных с прибора)

**Это самое интересное!** Протокол обмена через USB control transfer:

```java
// Метод j() — читает ИМЯ устройства
public static String j() {
    a aVar = g(null).h();
    byte[] bArr = new byte[16];
    // controlTransfer(128, 192, 0, 0, buffer, 16, timeout)
    aVar.connection.controlTransfer(128, 192, 0, 0, bArr, 16, 100);
    // Преобразует байты в строку (до первого нуля)
}

// Метод k() — читает СЕРИЙНЫЙ НОМЕР
public static String k() {
    a aVar = g(null).h();
    byte[] bArr = new byte[16];
    // controlTransfer(128, 196, 0, 0, buffer, 16, timeout)
    aVar.connection.controlTransfer(128, 196, 0, 0, bArr, 16, 100);
    // Фильтрует: только цифры (48-57) и заглавные буквы (65-90)
}
```

В `k2.b.j()` метод `o2.b.j()` используется как **первичный источник** имени устройства. USB имеет приоритет над Wi-Fi.
